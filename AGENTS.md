# Правила работы с проектом Crucian

Эти правила действуют для всего репозитория. §faststart

## Первый вход

1. Прочитать `docs/agent-fast-start.ru.md`.
2. Проверить `docs/current-implementation-status.ru.md` и `docs/AUDIT_V061_RU.md`.
3. Найти относящиеся к задаче §-теги в `docs/dev/tag-map.md` и читать только связанные документы.
4. Перед изменением архитектуры открыть `docs/architecture/decisions/README.ru.md`.
5. Перед изменением геометрии свериться с `MEASUREMENTS_REQUIRED_RU.md`; предварительные размеры нельзя выдавать за измеренные.

## Документация

- README остаются понятными пользователю; длинные технические объяснения принадлежат тематическим документам в `docs/`.
- Текущая реализация описывается в `docs/current-implementation-status.ru.md` и должна отличать `реализовано`, `проверено локально`, `требует стенда` и `только план`.
- Устойчивое архитектурное решение оформляется новым ADR. Принятый ADR не переписывается задним числом: изменение оформляется следующим ADR со статусом замены.
- Неочевидная причина решения фиксируется в тематическом документе и связывается стабильным §-тегом из `docs/dev/tag-map.md`.
- Изменение поведения, схемы, протокола, материалов или процесса проверки сопровождается обновлением связанной документации в той же сессии.
- Перед завершением выполнить `npm.cmd run quality:docs:all`, `npm.cmd test` и подходящие проверки из `npm.cmd run review:impact`.

## Инженерные границы

- Не менять размеры посадок древка, M125, подшипников и углепластиковой спицы без фактических измерений. §meas001
- Не считать токосъёмник несущей опорой и не проводить спицу через центральную ось. §mech001
- ASA предпочтительна для постоянной наружной жёсткой механики; PETG используется для прототипов, купонов и защищённых деталей; TPU не определяет соосность подшипников. §mat0001
- BLE-имя `Crucian` и часовой сервисный интервал после настоящего включения питания являются принятыми решениями. §ble0001
- Комбинированный модуль AHT20+BMP280 питается от 3,3 В; климатический отказ не должен управлять подсветкой. §env001
- Нельзя утверждать аппаратную проверку прошивки, Android, водозащиты или теплового режима без соответствующего физического теста. §status1
- Не добавлять лицензию от имени владельца без отдельного согласования.
- Не коммитить секреты, локальные пути, build/cache-каталоги, APK, PlatformIO output или архив передачи.

## Проверка по области

- Документы: `npm.cmd run quality:docs:all`.
- Каталог: `npm.cmd run catalog:check`.
- Локальные контракты: `npm.cmd test`.
- Прошивка: настоящая PlatformIO-сборка и затем стенд BLE/PWM/deep-sleep.
- Android: сборка Gradle и тест с реальным BLE-устройством.
- Механика: генерация моделей, проверка STL и печать тестовых купонов.

Зелёный локальный quality gate подтверждает только структуру репозитория, а не физическую работоспособность.
