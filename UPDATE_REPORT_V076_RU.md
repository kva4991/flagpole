# Подробный отчёт по кумулятивному обновлению v0.7.6

## 1. Основание и границы

Пакет подготовлен для `kva4991/flagpole` на базе `main` commit `14346190d702c292fded598f55fc431dd92b19ad`, версия источника — v0.7.5.

Обновление затрагивает:

- публичное имя проекта;
- представление ID в карточках и полноэкранном 3D;
- автоматическое размещение двухмерных выносок;
- компоновку трёх одно-материальных очередей печати;
- трактовку PETG-подложек/brim/raft;
- минимальный точный CAD-процесс build123d-mcp;
- документацию, ADR, тесты, производные изображения/GLB и контрольные суммы.

Электрическая схема, маршрут проводов, размеры корпуса, световой тоннель, мембрана, лямки, количество закладных, прошивочный BLE-протокол и физические посадки этой задачей не пересматриваются.

```text
Super_pommels_and_flag
```

Имя используется в каталоге, Android resources/Kotlin и видимой документации.

Это означает установку как отдельного приложения относительно старого `ru.quicktickets.crucian`.

## 3. Миниатюры без ID

Ранее overlay-чертежи использовали `annotatedPreview` одновременно как полноразмерный файл и изображение карточки. В 3D-карточках hotspots также отображались сразу после загрузки модели.

Принято:

- схема `catalog/drawings.json` повышена с 3 до 4, потому что чистая миниатюра стала обязательной частью контракта;
- у каждой 2D-карточки есть отдельное поле `thumbnail`;
- overlay-карточка показывает чистый `preview`, а по нажатию открывает `annotatedPreview`;
- разнесённый вид 112 использует чистый `preview_v06_exploded_PETG_TPU.png`;
- таблица ID 117 использует нейтральную проектную SVG-миниатюру без номеров;
- hotspots остаются в DOM карточного `<model-viewer>`, но скрыты CSS;
- легенда ID под карточкой сохраняется: она не перекрывает изображение и нужна для навигации.

Валидатор каталога отклоняет `thumbnail`, ссылающийся на `catalog/annotated/` или файл `_ids.png`.

## 4. Кнопка ID в полноэкранном просмотре

В верхней панели рядом с круглым крестиком добавлена отдельная нарисованная SVG-кнопка:

- пиктограмма глаза;
- подпись `ID`;
- состояние `aria-pressed`;
- динамические `title` и `aria-label`;
- перечёркнутый глаз при скрытых метках.

При открытии непечатной модели метки по умолчанию видимы. Нажатие переключает CSS-класс `ids-hidden` без повторной загрузки GLB. Для печатных раскладок, у которых hotspots отсутствуют, кнопка скрыта. Состояние сбрасывается при закрытии или выходе из Fullscreen API.

## 5. Более короткие двухмерные выноски

### Было

`labelPosition` являлся абсолютным центром рамки. Во многих карточках он находился у края листа, поэтому лидер шёл через половину схемы и мог пересекать другие элементы.

### Стало

`labelPosition` используется только как предпочтительное направление. Resolver:

1. строит несколько колец кандидатов вокруг `target`;
2. ставит плотные группы первыми;
3. штрафует пересечение рамок;
4. штрафует попадание линии через чужую рамку;
5. штрафует пересечение уже размещённых лидеров;
6. мягко штрафует прохождение через контрастные контуры исходного чертежа, кроме зоны у самой цели;
7. выбирает ближайшую допустимую рамку;
8. начинает линию на ближайшей границе рамки, а не из её центра.

Результат детерминирован и не зависит от системного шрифта. Генерируется `mechanical/CALLOUT_LAYOUT_REPORT_V076.json` с прежней и новой нормированной длиной лидеров, пересечениями и фактическими координатами. `--check` сравнивает как PNG, так и отчёт.

**Почему не перенесены вручную десятки `labelPosition`:** ручные координаты снова устареют после изменения чертежа. Resolver сохраняет намерение «с какой стороны лучше подписать», но адаптирует расстояние автоматически.

## 6. Компактные очереди печати

### Проблема

`generate_models_v06.py` хранил большие списки ручных XYZ-позиций. Между деталями оставались пустые зоны, а изменение габарита не приводило к автоматической перепроверке стола.

### Решение

Добавлен `mechanical/layout_packing.py`:

- работает с уже выбранной ориентацией печати;
- использует AABB фактической сетки;
- стол — 256 × 256 мм;
- резерв от края — 8 мм;
- PETG — минимум 6 мм между AABB;
- TPU 95A/85A — минимум 5 мм;
- крупные детали размещаются первыми по детерминированным полкам;
- итоговая сцена центрируется для удобного просмотра;
- при переполнении стола генерация завершается ошибкой;
- метрики записываются в `model_parameters_and_diagnostics_v06.json`.

**Почему зазор не сделан нулевым:** «ближе» не означает касание. Нужен запас от brim, неточности габарита и удобство выделения объектов в слайсере.

## 7. Что решено по PETG-подложкам

В текущем наборе печатных деталей отдельной жертвенной PETG-подложки под TPU нет. Ранее документация оставляла общее «допустимое исключение», которое можно было принять за уже спроектированную деталь.

Зафиксировано:

- `#petg-5` — реальная сервисная крышка, сопрягаемая с `#tpu85-1`, а не подложка для печати;
- TPU печатается отдельными очередями и устанавливается после печати;
- brim/raft создаётся профилем слайсера и не является каноническим физическим компонентом;
- добавлять фиктивную пластину в STL/GLB запрещено, потому что её можно ошибочно включить в BOM или напечатать как часть изделия;
- в карточках очередей это объясняется прямо.

То есть отсутствие подложек в прежних изображениях было не пропущенной геометрией, а неточной формулировкой документации. В v0.7.6 формулировка исправлена.

## 8. Какие CAD-навыки добавлены

Добавлен только процесс, который закрывает реальный пробел текущего проекта:

```text
pzfreo/build123d-mcp
modeling
drawing
repair
```

В репозитории сохранены:

- `mechanical/docs/BUILD123D_MCP_WORKFLOW_RU.md`;
- пример безопасной конфигурации `tools/cad/build123d-mcp.example.json`;
- короткая ссылка и обязательные границы в `AGENTS.md`;
- ADR-0029.

Не добавлены как обязательные:

- `text-to-cad` — дублирует проектную дисциплину `AGENTS.md`;
- `draftwright` — рассматривается после появления устойчивых STEP;
- `blender-industrial-kit` — Blender остаётся визуализатором, не производственным источником.

Пилот ограничен `#petg-6`, `#petg-10`, `#petg-5`. Существующий SDF/trimesh-генератор остаётся каноническим до отдельного принятия каждого B-Rep-переноса.

## 9. Версия

Версия повышается до v0.7.6. Причина — изменяются публичная идентичность, HTML-интерфейс, правила медиа, алгоритм аннотаций, GLB-раскладки, диагностические JSON, документация и quality gate. Сохранение v0.7.5 создало бы два несовместимых набора производных файлов под одним номером.

Технические имена файлов `v0_6` и текущие скрипты с суффиксом `v075` сохраняются для совместимости ссылок; их содержимое и метаданные соответствуют v0.7.6.

## 10. Новые долгосрочные решения

- ADR-0027 — чистые миниатюры, полноэкранный переключатель и auto-near-target callouts;
- ADR-0028 — компактные одно-материальные раскладки и отсутствие фиктивных PETG-подложек;
- ADR-0029 — ограниченный build123d-mcp CAD-контур.

## 11. Тесты

Добавлены:

- `catalogPresentationV076.test.mjs` — чистые миниатюры, публичное имя, кнопка ID и отчёт выносок;
- `printLayoutPolicyV076.test.mjs` — границы стола, зазоры и отсутствие backing geometry;
- `cadWorkflowV076.test.mjs` — только необходимые MCP-навыки и пилотные ID;
- `layout_packing.py --self-test`;
- `render_catalog_part_callouts_v075.py --self-test`.

`quality:gate` запускает оба Python self-test до каталоговых и Node-проверок. Дополнительно до упаковки выполнено двукратное применение к полному синтетическому checkout: первый запуск изменил источники и создал ZIP, второй не изменил ни одного файла (`changedPaths = 0`). Отдельно проверено, что исторические CI-свидетельства v0.7.5 не переименовываются в v0.7.6.

## 12. Порядок применения и регенерации

Применитель:

1. проверяет checkout и base commit;
2. обновляет только источники и документацию;
3. запускает identity generator;
4. полностью пересобирает механику и три GLB-раскладки;
5. пересобирает превью, схемы и компактные ID-выноски;
6. генерирует HTML;
7. обновляет SHA-256;
8. записывает честный текущий статус: локальный quality gate отдельно, исторический CI v0.7.5 отдельно, новый CI — pending до push владельца;
9. повторно запускает quality gate и `git diff --check` после обновления статуса, manifest и SHA-256;
10. создаёт полный `Super_pommels_and_flag_v0.7.6_cumulative_full.zip` из checkout.

Скрипт не выполняет `git add`, commit или push.

## 13. Ограничения

- Self-test пакета проверяет алгоритмы и идемпотентность, но не заменяет запуск на полном checkout.
- Финальные PNG/GLB и полный ZIP появляются после применения к локальному клону, потому что неизменённые бинарные файлы не дублируются в update bundle.
- Проверки сеток не подтверждают реальные посадки, прочность, герметичность, нагрев или печатный профиль.
- Build123d-процесс добавлен, но существующие 23 детали автоматически не конвертированы в B-Rep.
- Смена Android application ID создаёт отдельное приложение; автоматического переноса данных со старого package нет.
## 14. Контроль ложных заявлений о проверке

Глобальная замена `0.7.5 → 0.7.6` намеренно не применяется к `VALIDATION_STATUS_RU.md`, `docs/current-implementation-status.ru.md`, старым отчётам, архивным ADR и предыдущему manifest. После локального запуска применитель формирует новый статус отдельно. Поэтому успешный GitHub Actions run `30761888122` остаётся доказательством опубликованной v0.7.5, а не выдаётся за ещё не опубликованную v0.7.6.

`PROJECT_MANIFEST.json` сохраняет прежние `publication`/`validation` в полях `previousPublication` и `previousValidation`, пересчитывает file-count/bytes/largest-files по фактическому checkout и помечает новый GitHub Actions как ожидающий push владельца.
