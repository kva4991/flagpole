# #122 — Чистый шаблон рыбы для 16-мм неона v0.7.6 — A4

> **Статус:** текущий материал версии 0.7.6. Этот файл является единственным подробным текстовым описанием карточки #122. Краткий текст на странице каталога берётся из поля `summary` выше. Правило синхронного обновления: **§mediarationale1**.

## 0. Критический контракт

### Критические элементы — нельзя потерять

- Сохранить чистый контур рыбы для укладки круглого неона Ø16 мм.
- Сохранить габарит 300 × 250 мм и непрерывный маршрут неона.
- Оставить лист пригодным для переноса контура без служебных ID поверх шаблона.

### Запрещено

- Не использовать слово «ихтис» и не менять форму без синхронного размерного шаблона #123.
- Не задавать изгибы меньше допустимого радиуса реального неона.

### Проверить после генерации

- Сверить контур с размерным шаблоном #123 и флагом #109.
- Проверить масштаб печати и физическую укладку отрезка неона.

## 1. Назначение и границы

Чистый шаблон #122 хранит только геометрию рыбы и предназначен для переноса контура, примерки неона и подготовки ткани без размерных надписей. Он не должен обрастать постоянными ID или пояснениями внутри исходного SVG.

Карточка относится к разделу `drawings`, типу `drawing` и показывает полноразмерный подписанный вид. Она описывает, почему вид устроен именно так, но не превращает предварительные размеры в подтверждённые и не отменяет профильные документы/физические испытания.

## 3. Что показано

Исходник содержит внешний путь под круглый неон Ø16 мм, внутренний контур светоотражающей вставки тела, отдельную вставку хвоста и сквозной глаз. Материальные ID добавляются только в отдельную аннотированную PNG-копию каталога; чистая миниатюра остаётся без подписей.

Метаданные `calloutMode` определяют способ подписей. Для `overlay` исходник остаётся чистым и строится отдельная аннотированная копия; для `embedded` ID уже являются частью документа; для `hotspots` координаты хранятся в JSON и отображаются только viewer; для `exempt` выноски запрещены, поскольку это раскладка печати.

## 4. Почему изображено именно так

Отсутствие текста и размеров позволяет распечатать или спроецировать контур без риска переноса служебных надписей на ткань. Толстая линия относится к траектории 16-мм неона, тонкие линии — к отдельным вставкам; смешение толщин разрушило бы смысл выкройки. Форма «рыба» используется последовательно во всём проекте.

Ракурс, степень разнесения и набор показанных объектов являются частью инженерной коммуникации. Их нельзя менять только ради «красивой картинки»: изменение допустимо, когда новый вид лучше проверяет конкретный риск, сохраняет сопоставимость с соседними карточками и не скрывает обслуживаемость, крепёж, провод или функциональную поверхность.

## 5. Разбор элементов и ID

- `#004` — **Неон Ø16 мм**. Основная светящаяся 12-вольтовая лента по контуру рыбы. Управляется через MOSFET-модуль, а не напрямую от ESP32-C3. Внутренний ID в JSON остаётся `004`, на странице показывается ровно один префикс `#`.
- `#013` — **Oxford 210D**. Кандидат на основное полотно флага в форме рыбы. Яркий оранжевый цвет обеспечивает визуальную заметность, а PU-покрытие помогает ткани сопротивляться влаге и загрязнению. Внутренний ID в JSON остаётся `013`, на странице показывается ровно один префикс `#`.
- `#014` — **Рефлективная ткань**. Отдельные светоотражающие вставки внутри тела рыбы и в хвосте, заметные в свете фар и другой направленной внешней подсветки. Не заменяет основную ткань Oxford и внутреннюю LED-подсветку. Внутренний ID в JSON остаётся `014`, на странице показывается ровно один префикс `#`.
- `#025` — **Нить Tex 45**. Основная нить для швов флага из Oxford 210D и пришивания светоотражающих вставок. Непрерывное полиэфирное волокно лучше подходит для солнца и влаги, чем хлопок или хлопковая оплётка; bonded-обработка удерживает сложение нити и облегчает шитьё в разных направлениях. Внутренний ID в JSON остаётся `025`, на странице показывается ровно один префикс `#`.

Все видимые идентификаторы нормализуются функцией отображения: `001` становится `#001`, а уже префиксный `#petg-1` остаётся `#petg-1`. Двойной префикс `##` запрещён. Feature-ID вида `#petg-1_закладная1` должны иметь собственный реестр и родительскую связь; они не становятся новыми позициями BOM.

## 6. Сборочная, эксплуатационная и сервисная логика

Перед раскроем проверяют масштаб A4 контрольным размером, затем переносят контуры на ткань с учётом припусков конкретного способа шитья. Неон прикладывают физически и проверяют минимальный радиус изгиба. Глаз вырезают только после стабилизации ткани и проверки положения отражателя.

При проверке необходимо различать рабочее положение, разнесённое presentation-положение и печатную ориентацию. Нельзя копировать presentation-трансформацию в каноническую STL, а непечатные референсы нельзя включать в экспорт печатных деталей. Любая обслуживаемая гайка, прокладка, окно, мембрана или плата должна оставаться заменяемой без разрушения соседнего узла, если профильный документ не закрепляет обратное.

## 7. Предварительные параметры и неподтверждённые допущения

Чистый шаблон не содержит припусков, компенсации толщины неона, швейной технологии и фактической деформации ткани. Окончательная форма зависит от реального неона, его торцевого вывода, массы и способности держать радиус.

Слова «помещается», «герметично», «выдерживает», «соосно», «безопасно по температуре» и «готово к печати» допустимы только после соответствующей проверки. Замкнутая STL/GLB, корректный рендер и зелёный тест JSON подтверждают цифровой слой, но не физическую посадку, прочность, IP-рейтинг, долговечность или поведение реальной электроники.

## 8. Что обновлять одновременно

При любом изменении карточки #122 в одном изменении должны быть проверены и при необходимости обновлены:

1. первичный источник `fish_template_clean_A4_landscape.svg` и основной файл `fish_template_clean_A4_landscape.svg`;
2. растровый постер/превью, чистая миниатюра и аннотированная копия, если они применимы;
3. запись #122 в `catalog/drawings.json`, включая пути, версию, статус, `kind`, `calloutMode`, координаты и `descriptionFile`;
4. этот файл `catalog/media-descriptions/122.md`, включая причины решений, ограничения и список проверок;
5. профильные документы, перечисленные в разделе 2, но только если изменилось общее требование, а не формулировка конкретного вида;
6. генераторы, валидаторы и тесты каталога/моделей;
7. `CHECKSUMS_SHA256.txt`, `PROJECT_MANIFEST.json` и отчёты выпуска — последними, после регенерации.

Содержательное описание этой карточки нельзя повторно хранить в поле `description` JSON, в вручную отредактированном `catalog.html` или в соседнем README. Разрешены только короткая ссылка и общая политика. Это устраняет расхождение двух текстов.

Для этой карточки дополнительно проверить:

- основной файл и все производные пути существуют и открываются;
- заголовок на странице показывает `#122` с одним символом `#`;
- краткий текст карточки совпадает с `summary` этого файла, а ссылка ведёт именно на `122.md`;
- миниатюра остаётся чистой; ID появляются только в разрешённом полноразмерном слое;
- подписи указывают на нужные тела и не описывают отсутствующую геометрию;
- масштаб, ориентация, линии, подписи и печатный контур визуально сверены с первичным источником;
- профильные ограничения и список неподтверждённых измерений не исчезли при упрощении текста.

Физические проверки из профильных документов выполняются отдельно и их результат записывается в проект, а не подразумевается из вида.
