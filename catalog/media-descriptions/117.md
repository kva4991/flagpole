# #117 — Таблица идентификаторов печатных деталей v0.7.6

> **Статус:** текущий материал версии 0.7.6. Этот файл является единственным подробным текстовым описанием карточки #117. Краткий текст на странице каталога берётся из поля `summary` выше. Правило синхронного обновления: **§mediarationale1**.

## 0. Критический контракт

### Критические элементы — нельзя потерять

- Сохранить полный реестр 23 печатных деталей без пропусков и дублей.
- Сохранять стабильные ID и однозначное соответствие материалу, имени и STL.
- Показывать `#` ровно один раз перед каждым ID.

### Запрещено

- Не перенумеровывать детали из-за смены CAD-движка или ракурса.
- Не добавлять feature-ID закладных как отдельные позиции BOM.

### Проверить после генерации

- Сверить таблицу с JSON-реестром и всеми карточками моделей/раскладок.
- Проверить существование каждого STL и уникальность каждого ID.

## 1. Назначение и границы

Таблица #117 — человекочитаемое отображение канонического реестра всех печатных деталей. Она отвечает на вопрос, какой ID соответствует какому материалу, STL и назначению, и не должна редактироваться отдельно от JSON-реестра.

Карточка относится к разделу `drawings`, типу `drawing` и показывает полноразмерный подписанный вид. Она описывает, почему вид устроен именно так, но не превращает предварительные размеры в подтверждённые и не отменяет профильные документы/физические испытания.

## 3. Что показано

Лист содержит 10 PETG, 10 TPU 95A и 3 TPU 85A позиции, количество каждой детали, русское назначение и относительный путь к STL. Одинаковый ID должен сохраняться на чертежах, в GLB hotspots, именах документации и отчётах сравнения.

Метаданные `calloutMode` определяют способ подписей. Для `overlay` исходник остаётся чистым и строится отдельная аннотированная копия; для `embedded` ID уже являются частью документа; для `hotspots` координаты хранятся в JSON и отображаются только viewer; для `exempt` выноски запрещены, поскольку это раскладка печати.

## 4. Почему изображено именно так

Единый реестр предотвращает появление параллельных названий вроде «крышка», «верхняя крышка» и «корпус датчика» без однозначной связи. Табличный вид имеет `calloutMode: embedded`, потому что сам документ уже состоит из ID и не нуждается во втором слое выносок.

Ракурс, степень разнесения и набор показанных объектов являются частью инженерной коммуникации. Их нельзя менять только ради «красивой картинки»: изменение допустимо, когда новый вид лучше проверяет конкретный риск, сохраняет сопоставимость с соседними карточками и не скрывает обслуживаемость, крепёж, провод или функциональную поверхность.

## 6. Сборочная, эксплуатационная и сервисная логика

При добавлении, удалении или переименовании детали сначала изменяют `mechanical/part_id_registry_v06.json`, затем генератор, STL, разнесённые виды, каталожные карточки, описания и тесты. Освободившийся ID нельзя автоматически выдавать другой геометрии: стабильность важнее плотной нумерации.

При проверке необходимо различать рабочее положение, разнесённое presentation-положение и печатную ориентацию. Нельзя копировать presentation-трансформацию в каноническую STL, а непечатные референсы нельзя включать в экспорт печатных деталей. Любая обслуживаемая гайка, прокладка, окно, мембрана или плата должна оставаться заменяемой без разрушения соседнего узла, если профильный документ не закрепляет обратное.

## 7. Предварительные параметры и неподтверждённые допущения

Таблица фиксирует логическую идентичность, но не подтверждает, что STL напечатан, что количество достаточно для запасных частей или что материал окончательно выбран. Переход PETG→ASA требует новых купонов, но не нового ID только из-за материала/движка.

Слова «помещается», «герметично», «выдерживает», «соосно», «безопасно по температуре» и «готово к печати» допустимы только после соответствующей проверки. Замкнутая STL/GLB, корректный рендер и зелёный тест JSON подтверждают цифровой слой, но не физическую посадку, прочность, IP-рейтинг, долговечность или поведение реальной электроники.

## 8. Что обновлять одновременно

При любом изменении карточки #117 в одном изменении должны быть проверены и при необходимости обновлены:

1. первичный источник `mechanical/generate_reference_diagrams_v06.py` и основной файл `mechanical/part_id_table_v06.svg`;
2. растровый постер/превью, чистая миниатюра и аннотированная копия, если они применимы;
3. запись #117 в `catalog/drawings.json`, включая пути, версию, статус, `kind`, `calloutMode`, координаты и `descriptionFile`;
4. этот файл `catalog/media-descriptions/117.md`, включая причины решений, ограничения и список проверок;
5. профильные документы, перечисленные в разделе 2, но только если изменилось общее требование, а не формулировка конкретного вида;
6. генераторы, валидаторы и тесты каталога/моделей;
7. `CHECKSUMS_SHA256.txt`, `PROJECT_MANIFEST.json` и отчёты выпуска — последними, после регенерации.

Содержательное описание этой карточки нельзя повторно хранить в поле `description` JSON, в вручную отредактированном `catalog.html` или в соседнем README. Разрешены только короткая ссылка и общая политика. Это устраняет расхождение двух текстов.

## 9. Проверка после изменения

Минимальная цифровая проверка:

```powershell
npm.cmd run media:descriptions:check
npm.cmd run catalog:generate
npm.cmd run catalog:check
npm.cmd test
npm.cmd run quality:docs:all
npm.cmd run checksums:update
npm.cmd run checksums:check
```

Для этой карточки дополнительно проверить:

- основной файл и все производные пути существуют и открываются;
- заголовок на странице показывает `#117` с одним символом `#`;
- краткий текст карточки совпадает с `summary` этого файла, а ссылка ведёт именно на `117.md`;
- миниатюра остаётся чистой; ID появляются только в разрешённом полноразмерном слое;
- подписи указывают на нужные тела и не описывают отсутствующую геометрию;
- масштаб, ориентация, линии, подписи и печатный контур визуально сверены с первичным источником;
- профильные ограничения и список неподтверждённых измерений не исчезли при упрощении текста.

Физические проверки из профильных документов выполняются отдельно и их результат записывается в проект, а не подразумевается из вида.
