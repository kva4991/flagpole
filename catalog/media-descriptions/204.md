## 0. Критический контракт

### Критические элементы — нельзя потерять

- Сохранить все 23 печатные детали ровно по одному разу в именованных узлах GLB.
- Все 23 тела должны быть native build123d/OCP B-Rep без legacy mesh-узлов.
- Сохранить материал/ID каждой детали и чистые миниатюры без hotspots.
- Разнесение должно быть только presentation-трансформацией канонических тел.
- `#tpu95-10` остаётся цельной деталью с двумя закрытыми сквозными каналами.
- Посадка `#petg-2_ввод_флага` остаётся глухой; четыре гайки крышки и две гайки `#petg-8` не имеют наружных боковых загрузочных окон.
- Четыре внутренние стойки сервисной крышки имеют диаметр 10 мм и длину 18 мм; электронная полость не вырезает их сечение.
- В центрирующей юбке крышки предусмотрены четыре внутренние выборки Ø10,5 мм под усиленные стойки; наружная пластина крышки остаётся замкнутой.
- Непрерывная прокладка перенесена на внутреннюю PETG-полку между электроникой и четырьмя винтами; винтовые отверстия остаются во внешней мокрой зоне и не пересекают канавку.

### Запрещено

- Не отправлять `#petg-1…#petg-4` и старые подшипниковые купоны в печать до примерки #40101–#40106 и регенерации центрального узла.

- Не дублировать сервисную крышку или другие детали ради разнесения.
- Не включать текстовые сетки, непечатные тела или крепёж в печатные STL.
- Не запускать старые генераторы справочных схем и непечатных интерактивных сцен при регенерации #204.

## 3. Что показано

GLB содержит ровно 23 именованных native build123d-узла: десять `PETG_*`, десять `TPU95_*` и три `TPU85_*`. Hotspots используют ID деталей и зарегистрированные feature-ID. Вариант с крепежом добавляет только `REF_FASTENER_*` и не используется для печати.

Метаданные `calloutMode` определяют способ подписей. Для `overlay` исходник остаётся чистым и строится отдельная аннотированная копия; для `embedded` ID уже являются частью документа; для `hotspots` координаты хранятся в JSON и отображаются только viewer; для `exempt` выноски запрещены, поскольку это раскладка печати.

## 4. Почему изображено именно так

Каждая деталь представлена отдельным узлом, поэтому её можно диагностировать по имени и количеству. Разнесение выполняется только трансформациями; дубликаты канонических сеток запрещены. Hotspots хранятся в HTML, а не как текстовая геометрия GLB, что уменьшает LFS и исключает попадание надписей в печать.

Ракурс, степень разнесения и набор показанных объектов являются частью инженерной коммуникации. Их нельзя менять только ради «красивой картинки»: изменение допустимо, когда новый вид лучше проверяет конкретный риск, сохраняет сопоставимость с соседними карточками и не скрывает обслуживаемость, крепёж, провод или функциональную поверхность.

## 6. Сборочная, эксплуатационная и сервисная логика

Модель загружается только после клика. В карточке hotspots скрыты. В полноэкранном viewer одна кнопка переключает ID/feature-ID, вторая переключает базовый GLB и облегчённый вариант с крепежом. Для реальной сборки пользователь переходит к #205, #124 и специализированным сечениям; эта сцена служит проверкой комплектности.

После снятия крышки четыре M3-гайки доступны сверху в глухих колодцах. Две
гайки крепления `#petg-8` доступны тем же способом после снятия кармана. Под
каждой гайкой остаётся короткое глухое углубление под конец винта; наружные
стенки бокса не имеют боковых загрузочных окон.

При проверке необходимо различать рабочее положение, разнесённое presentation-положение и печатную ориентацию. Нельзя копировать presentation-трансформацию в каноническую STL, а непечатные референсы нельзя включать в экспорт печатных деталей. Любая обслуживаемая гайка, прокладка, окно, мембрана или плата должна оставаться заменяемой без разрушения соседнего узла, если профильный документ не закрепляет обратное.

До физического выбора посадок, переработки ротора и генерации #204 служит только обзором остальных конструктивных приёмов. §bearingadapter1

Отчёт подтверждает валидность B-Rep и замкнутость экспортированных STL, но не подтверждает реальные посадки или физическое качество. Координаты hotspot необходимо перепроверять после любого изменения положения/размера детали. Размер GLB зависит от тесселяции, а не от массы печати.

Слова «помещается», «герметично», «выдерживает», «соосно», «безопасно по температуре» и «готово к печати» допустимы только после соответствующей проверки. Замкнутая STL/GLB, корректный рендер и зелёный тест JSON подтверждают цифровой слой, но не физическую посадку, прочность, IP-рейтинг, долговечность или поведение реальной электроники.

## 8. Что обновлять одновременно

При любом изменении карточки #204 в одном изменении должны быть проверены и при необходимости обновлены:

1. первичный источник `mechanical/generate_build123d_canonical_v076.py`, исходник #401 и его единый JSON размеров, 23 STEP/STL, основной GLB и вариант с крепежом;
2. растровый постер/превью, чистая миниатюра и аннотированная копия, если они применимы;
3. запись #204 в `catalog/drawings.json`, включая пути, версию, статус, `kind`, `calloutMode`, координаты и `descriptionFile`;
4. этот файл `catalog/media-descriptions/204.md`, включая причины решений, ограничения и список проверок;
5. профильные документы, перечисленные в разделе 2, но только если изменилось общее требование, а не формулировка конкретного вида;
6. генераторы, валидаторы и тесты каталога/моделей;
7. `CHECKSUMS_SHA256.txt`, `PROJECT_MANIFEST.json` и отчёты выпуска — последними, после регенерации.

Содержательное описание этой карточки нельзя повторно хранить в поле `description` JSON, в вручную отредактированном `catalog.html` или в соседнем README. Разрешены только короткая ссылка и общая политика. Это устраняет расхождение двух текстов.

## 9. Проверка после изменения

Минимальная цифровая проверка:

```powershell
npm.cmd run media:descriptions:check
npm.cmd run catalog:generate
npm.cmd run catalog:check
npm.cmd test
npm.cmd run quality:docs:all
npm.cmd run checksums:update
npm.cmd run checksums:check
```

Для этой карточки дополнительно проверить:

- основной файл и все производные пути существуют и открываются;
- заголовок на странице показывает `#204` с одним символом `#`;
- краткий текст карточки совпадает с `summary` этого файла, а ссылка ведёт именно на `204.md`;
- миниатюра остаётся чистой; ID появляются только в разрешённом полноразмерном слое;
- подписи указывают на нужные тела и не описывают отсутствующую геометрию;
- GLB не получает `src` до клика; после загрузки узлы непрозрачны, hotspots работают в полноэкранном viewer;
- профильные ограничения и список неподтверждённых измерений не исчезли при упрощении текста.

Физические проверки из профильных документов выполняются отдельно и их результат записывается в проект, а не подразумевается из вида.
