# #102 — Карта клемм, GPIO и разъёмов v0.7.6 — A4

> **Статус:** текущий материал версии 0.7.6. Этот файл является единственным подробным текстовым описанием карточки #102. Краткий текст на странице каталога берётся из поля `summary` выше. Правило синхронного обновления: **§mediarationale1**.

## 0. Критический контракт

### Критические элементы — нельзя потерять

- Сохранить GPIO3 для PWM и GPIO4/GPIO5 для общей I²C-шины.
- Показать полярность, направление и назначение каждой клеммы и герметичного разъёма.
- Сохранить раздельность силовых и сигнальных соединений.

### Запрещено

- Не назначать контакты по цвету китайского шлейфа без прозвонки.
- Не переставлять GPIO без синхронной правки обеих прошивок, Android-контракта и схемы #101.

### Проверить после генерации

- Сверить карту с `config.h`, основной схемой #101 и маркировкой плат.
- Проверить, что подписи не перекрывают клеммы и у каждого ID ровно один `#`.

## 1. Назначение и границы

Карта клемм и GPIO — монтажный спутник схемы #101. Она переводит функциональные линии в конкретные имена контактов, чтобы при сборке не приходилось угадывать, куда подключать каждую жилу. Карта не заменяет принципиальную схему, распиновку фактической платы продавца и прозвонку разъёмов.

Карточка относится к разделу `drawings`, типу `drawing` и показывает полноразмерный подписанный вид. Она описывает, почему вид устроен именно так, но не превращает предварительные размеры в подтверждённые и не отменяет профильные документы/физические испытания.

## 3. Что показано

Таблица перечисляет вход +12 В/GND, оба канала M125, VIN/VOUT DC-DC, GPIO3/4/5 и 3V3 ESP32-C3, клеммы VEML7700 и AHT20+BMP280, Source/Drain/Gate LR7843 и два контакта J1. Отдельно записаны адреса AHT20 и BMP280, требование единственного ввода через #tpu95-3/#tpu95-4 и сервисная петля 30–40 мм.

Метаданные `calloutMode` определяют способ подписей. Для `overlay` исходник остаётся чистым и строится отдельная аннотированная копия; для `embedded` ID уже являются частью документа; для `hotspots` координаты хранятся в JSON и отображаются только viewer; для `exempt` выноски запрещены, поскольку это раскладка печати.

## 4. Почему изображено именно так

Табличная форма выбрана потому, что на этапе монтажа важнее однозначная пара «узел — контакт — назначение», чем графический маршрут сигнала. Повтор ID из каталога исключает ситуацию, когда одна и та же плата названа в разных документах «контроллером», «ESP» и «SuperMini» без связи. Сведения о цветах проводов намеренно заменены формулировкой «определить прозвонкой»: китайские жгуты и пары разъёмов не гарантируют одинаковую цветовую кодировку.

Ракурс, степень разнесения и набор показанных объектов являются частью инженерной коммуникации. Их нельзя менять только ради «красивой картинки»: изменение допустимо, когда новый вид лучше проверяет конкретный риск, сохраняет сопоставимость с соседними карточками и не скрывает обслуживаемость, крепёж, провод или функциональную поверхность.

## 5. Разбор элементов и ID

- `#001` — **ESP32-C3**. Основной микроконтроллер. Управляет BLE, PWM подсветки, датчиком освещённости и логикой режима дня/ночи. Внутренний ID в JSON остаётся `001`, на странице показывается ровно один префикс `#`.
- `#005` — **MOSFET**. Силовой низковольтный ключ коммутирует 12-вольтовую подсветку и принимает PWM-сигнал ESP32-C3. Оптопара отделяет управляющую сторону от силовой при правильном подключении модуля. Внутренний ID в JSON остаётся `005`, на странице показывается ровно один префикс `#`.
- `#006` — **DC-DC**. Понижает стабилизированные 12 В системы до 5 В для питания ESP32-C3 и низковольтной периферии. Для выбранной версии 5 В вход 12 В находится внутри заявленного диапазона 6–28 В. Внутренний ID в JSON остаётся `006`, на странице показывается ровно один префикс `#`.
- `#002` — **VEML7700**. Датчик освещённости. Нужен для автоматического включения и регулировки яркости по внешнему свету. Внутренний ID в JSON остаётся `002`, на странице показывается ровно один префикс `#`.
- `#009` — **AHT20+BMP280**. Выбранный единый климатический модуль Crucian: AHT20 измеряет температуру и влажность, BMP280 — атмосферное давление и резервную температуру. Оба датчика работают на общей I²C-шине через один четырёхконтактный разъём. Внутренний ID в JSON остаётся `009`, на странице показывается ровно один префикс `#`.
- `#003` — **M125**. Двухканальный токосъёмник передаёт питание на вращающуюся подсветку внутри флагштока. Он не является подшипником и не должен воспринимать механическую нагрузку конструкции. Внутренний ID в JSON остаётся `003`, на странице показывается ровно один префикс `#`.

Все видимые идентификаторы нормализуются функцией отображения: `001` становится `#001`, а уже префиксный `#petg-1` остаётся `#petg-1`. Двойной префикс `##` запрещён. Feature-ID вида `#petg-1_закладная1` должны иметь собственный реестр и родительскую связь; они не становятся новыми позициями BOM.

## 6. Сборочная, эксплуатационная и сервисная логика

Работать по строкам сверху вниз: подключить вход и токосъёмник, проверить DC-DC, затем ESP32, после этого датчики, и только в конце силовой ключ и внешний разъём. На собранном устройстве таблица служит картой для измерения напряжений и поиска обрыва. При замене платы нужно обновлять не только название контакта, но и #101, прошивку, BOM, компоновку #125 и подробное описание этой карточки.

При проверке необходимо различать рабочее положение, разнесённое presentation-положение и печатную ориентацию. Нельзя копировать presentation-трансформацию в каноническую STL, а непечатные референсы нельзя включать в экспорт печатных деталей. Любая обслуживаемая гайка, прокладка, окно, мембрана или плата должна оставаться заменяемой без разрушения соседнего узла, если профильный документ не закрепляет обратное.

## 7. Предварительные параметры и неподтверждённые допущения

Требуют подтверждения физические надписи на модулях, направление нумерации J1, распиновка конкретного MOSFET-модуля, наличие развязки земли на оптопаре, уровни GPIO и расположение USB-C/кнопок. Адрес BMP280 0x76/0x77 зависит от состояния вывода SDO реальной платы.

Слова «помещается», «герметично», «выдерживает», «соосно», «безопасно по температуре» и «готово к печати» допустимы только после соответствующей проверки. Замкнутая STL/GLB, корректный рендер и зелёный тест JSON подтверждают цифровой слой, но не физическую посадку, прочность, IP-рейтинг, долговечность или поведение реальной электроники.

## 8. Что обновлять одновременно

При любом изменении карточки #102 в одном изменении должны быть проверены и при необходимости обновлены:

1. первичный источник `electronics/generate_electronics_diagrams_v075.py` и основной файл `electronics/electronics_terminal_map_A4.svg`;
2. растровый постер/превью, чистая миниатюра и аннотированная копия, если они применимы;
3. запись #102 в `catalog/drawings.json`, включая пути, версию, статус, `kind`, `calloutMode`, координаты и `descriptionFile`;
4. этот файл `catalog/media-descriptions/102.md`, включая причины решений, ограничения и список проверок;
5. профильные документы, перечисленные в разделе 2, но только если изменилось общее требование, а не формулировка конкретного вида;
6. генераторы, валидаторы и тесты каталога/моделей;
7. `CHECKSUMS_SHA256.txt`, `PROJECT_MANIFEST.json` и отчёты выпуска — последними, после регенерации.

Содержательное описание этой карточки нельзя повторно хранить в поле `description` JSON, в вручную отредактированном `catalog.html` или в соседнем README. Разрешены только короткая ссылка и общая политика. Это устраняет расхождение двух текстов.

- масштаб, ориентация, линии, подписи и печатный контур визуально сверены с первичным источником;
- профильные ограничения и список неподтверждённых измерений не исчезли при упрощении текста.

Физические проверки из профильных документов выполняются отдельно и их результат записывается в проект, а не подразумевается из вида.
