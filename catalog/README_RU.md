## Источники

- `catalog/components.json` — карточки компонентов и материалов;
- `catalog/physical-components.json` — единственный редактируемый источник физических размеров, массы, статуса измерения и потребности в дополнительных замерах для каждого component-ID; §physicalcomponents1
- `catalog/drawings.json` — только актуальные чертежи, модели и очереди печати; он хранит структуру карточек и ссылки `descriptionFile`, но не подробные пояснения;
- `mechanical/cad_drafts/*.json`, перечисленные в `catalogPolicy.cadDraftSources`, — единые размерные источники ещё не сгенерированных CAD-заготовок; сайт показывает их без выдуманного PNG/STL/GLB;
- `catalog/media-descriptions/<ID>.md` — единственный подробный текст по конкретному медиа-ID: что показано, почему принято такое изображение/геометрия, какие допущения действуют и что обновлять одновременно; §mediarationale1
- `mechanical/part_id_registry_v06.json` — канонические ID печатных деталей;
- `VERSION.txt` — единственная версия, допустимая в рабочем каталоге;
- `scripts/generateComponentCatalog.mjs` — генератор `catalog/catalog.html`;
- `mechanical/render_catalog_part_callouts_v075.py` — генератор подписанных PNG-копий.

`catalog/catalog.html` — производный файл. Вручную его не редактировать.

## Политика current-only

Медиа-массивы рабочей вкладки «Чертежи и 3D» показывают только `status: "current"`. Любая медиа-запись с `historical`/`reference` либо версией, отличной от `VERSION.txt`, останавливает генерацию с ошибкой. Единственное немедийное исключение — отдельный блок исходных CAD-заготовок со статусом `source-only-not-generated`: у него по определению нет производного файла. Исторические файлы могут лежать в репозитории, но не должны присутствовать в массивах рабочего каталога.

Отдельной вкладки «Новый CAD» нет. Экспериментальные модели не публикуются в рабочем каталоге. Исходная заготовка без производных файлов может отображаться только в существующей вкладке «Чертежи и 3D», если её JSON перечислен в `catalogPolicy.cadDraftSources`, имеет статус `source-only-not-generated`, содержит размеры, зависимости и ссылку на воспроизводимый источник. Такой блок нельзя выдавать за готовую к печати модель.

Поэтому карточки наподобие «Общий вид сборки v0.5 — интерактивно» или «Раскладка TPU v0.5 — историческая» не скрываются CSS и не фильтруются после загрузки: их вообще нет в источнике рабочего HTML.

## ID-выноски

Каждый непечатный чертёж обязан использовать `calloutMode: "overlay"` или `embedded`. Каждая непечатная модель обязана использовать `calloutMode: "hotspots"`. Допустимы только существующие ID компонентов и печатных деталей.

Раскладки печати — единственное исключение. Они получают `kind: "print-layout"`, `calloutMode: "exempt"` и объяснение причины. Подписи на них запрещены, чтобы не закрывать ориентацию, контуры и зазоры.

Подробная схема полей и порядок выпуска описаны в `docs/CATALOG_MEDIA_POLICY_RU.md`, ADR-0026 и ADR-0032.

## Подробные описания по ID

Каждая запись из массивов `drawings`, `models` и `printSessions` имеет ровно один файл `catalog/media-descriptions/<ID>.md`. Имя файла, `id` во front matter и ID карточки должны совпадать. Перед изменением чертежа, модели, ракурса, выноски, посадки, упрощённого референса или смысла карточки агент обязан прочитать этот файл полностью. После изменения его обновляют в той же правке вместе с первичным CAD/SVG-источником и производными файлами.

Подробное объяснение не дублируется в `drawings.json`: поле `description` запрещено. Тематические документы в `mechanical/docs/` сохраняются, потому что описывают подсистему сразу для нескольких медиа; ID-файл даёт именно контекст конкретного изображения или модели и ссылается на эти документы. Краткая аннотация карточки берётся из `summary` front matter, а полный текст открывается ссылкой «Подробное описание #ID».

Контракт, существование основного файла/источника и отсутствие повторяющегося rationale вне ID-папки проверяются командой:

```powershell
npm.cmd run media:descriptions:check
```

## Чистые миниатюры и полноэкранные ID

Карточки 2D используют поле `thumbnail` и всегда показывают чистый исходный preview. Подписанная `annotatedPreview` открывается только как полный документ. В карточках 3D hotspots скрыты, но при переходе на весь экран копируются в viewer. Кнопка с пиктограммой глаза и надписью `ID` рядом с крестиком позволяет временно скрыть или вернуть их.

`labelPosition` задаёт предпочтительное направление. Фактическую близкую позицию выбирает `render_catalog_part_callouts_v075.py`; итоговые метрики записываются в `mechanical/CALLOUT_LAYOUT_REPORT_V076.json`.
<!-- v076-clean-thumbnails:end -->

Размерный SVG и базовый PNG должны быть пригодны для инженерной проверки и повторного использования. Выноски строятся как отдельные PNG в `catalog/annotated/`; пользователь видит подписанную версию, а рядом получает ссылку «Исходник без выносок». ID рисуются встроенным пиксельным алфавитом и не зависят от установленных в ОС шрифтов.

В GLB подписи реализуются hotspots web-компонента `<model-viewer>`. Текст не превращается в сетку и не попадает в STL/печать. Hotspots копируются в полноэкранный режим.

## Компоненты

ID компонентов состоят из трёх цифр и идут без пропусков. `imageStatus` принимает `confirmed`, `listing`, `reference` или `placeholder`. Справочная фотография не подтверждает конкретную купленную модель; неподтверждённые характеристики явно отмечаются в тексте.

`components.json` хранит назначение, названия, электрические характеристики и ссылки, но не геометрические размеры. Все измеренные, расчётные, стандартные, заявленные продавцом и предварительные физические величины записываются только в `physical-components.json`. Сайт объединяет оба источника по ID и создаёт постоянные адреса `catalog.html#component-001` … `catalog.html#component-025`. Текстовые документы ссылаются на такой адрес вместо копирования числа. Размеры печатных деталей остаются в параметрическом CAD и его отчёте, а не переносятся в реестр покупных компонентов.

Если владелец прислал новый замер, агент обновляет соответствующую запись `measurements`, статус и источник. Поле `needs` сохраняет только ещё отсутствующие данные. Ручное дублирование числа в `components.json`, актуальном README или медиа-описании запрещено; исторические ADR и отчёты могут сохранять значения времени принятия решения, если явно остаются историческими.

## Перегенерация

Из корня проекта:

```powershell
npm.cmd run media:descriptions:check
npm.cmd run catalog:generate
npm.cmd run catalog:check
npm.cmd run models:semantics:check
```

Npm-команды используют `scripts/runPython.mjs`: на Windows поддерживается `py -3`, на Linux/macOS — `python3`, также можно задать `FLAGPOLE_PYTHON`.

Для полного выпуска сначала перегенерируются механика, схемы и превью, затем слой выносок и HTML.

## Локальный просмотр

Вес каждого изображения, постера и GLB выводится непосредственно в карточке. Генератор вычисляет его из текущего файла, а для Git LFS — из поля `size` указателя, поэтому после замены медиа значение обновляется автоматически при `catalog:generate` и не хранится вручную в JSON.

```powershell
py -m http.server 8080 --bind 127.0.0.1
```

Открыть:

```text
http://127.0.0.1:8080/catalog/catalog.html
```

Привязка к `127.0.0.1` обязательна. Для GLB нужен HTTP-сервер; из `file://` браузер может блокировать локальную модель. Интернет используется только для загрузки `<model-viewer>`, сами GLB остаются локальными.
