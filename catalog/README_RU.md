# Каталог компонентов и локальная HTML-страница

<!-- §catalog -->

Этот каталог адаптирован под проект Crucian по той же идее, что и инструкция из другого проекта:

- `catalog/components.json` хранит категории и редактируемые данные компонентов;
- `catalog/drawings.json` хранит перечень чертежей, превью и 3D-моделей;
- генератор `scripts/generateComponentCatalog.mjs` строит HTML-страницу `catalog/catalog.html` с двумя вкладками;
- отдельный backend не нужен;
- при необходимости страницу можно открывать локально через Python mini-server.

## Структура

```text
project/
├── catalog/
│   ├── components.json
│   ├── drawings.json
│   ├── catalog.html
│   ├── images/
│   └── README_RU.md
└── scripts/
    └── generateComponentCatalog.mjs
```

## Поля строки каталога

- `id` — внутренний идентификатор позиции;
- `category` — идентификатор категории из массива `categories`;
- `image` — имя локального файла с изображением;
- `aliases` — возможные названия, по которым компонент можно искать;
- `purpose` — пояснение, зачем он нужен;
- `links` — список ссылок на описание или покупку.
- `imageStatus` — `confirmed` для фото реального экземпляра, `listing` для фото продавца, `reference` для справочной иллюстрации из внешнего источника или `placeholder` для временного эскиза;
- `additionalImages` — необязательные дополнительные виды детали с подписью;
- `specifications` — необязательный список кратких пар «параметр — значение»;
- `missing` — что именно нужно прислать для завершения карточки.

## Правило для изображений

- В каталог добавляются фотографии компонента, его полезные виды, размерные изображения и наглядные схемы подключения.
- Если для отдельной детали — например резистора, конденсатора, предохранителя, термистора или подшипника — пользователь не прислал фото, подбирается справочное изображение из источника с понятной лицензией. Файл сохраняется локально, источник, автор и лицензия указываются в карточке, а `imageStatus` устанавливается в `reference`.
- Справочное изображение показывает только внешний тип детали и не подтверждает производителя, модель, номинал, размеры или факт покупки. После получения оно заменяется фотографией реального экземпляра.
- Скриншоты, состоящие только из текста, списков характеристик или таблиц, не добавляются и не хранятся как изображения каталога.
- Полезный текст с таких скриншотов распознаётся и переносится в `purpose`, `specifications` или `missing`; рекламные формулировки отбрасываются.
- Текстовое изображение допустимо только тогда, когда оно одновременно является необходимой наглядной схемой и смысл потеряется при переносе в обычный текст.
- Если характеристика взята из карточки продавца и не проверена на реальном экземпляре, это явно отмечается в тексте.

HTML сохраняет пять запрошенных колонок. Служебные поля показываются внутри карточки
как пометки «нужно фото» и «нужно уточнить».

Компоненты автоматически группируются и фильтруются по категориям. Идентификаторы
ID компонентов `001`…`099`, чертежей `101`…`199` и 3D-моделей `201`…`299` состоят только из трёх цифр. Компонентные ID идут без пропусков: генератор проверяет это правило. В JSON все ID хранятся строками, чтобы ведущие нули не терялись.

## Вкладка «Чертежи и 3D»

Вторая вкладка строится из `catalog/drawings.json`:

- чертежи и виды показываются как локальные PNG-превью со ссылкой на исходный SVG или PNG;
- GLB-модели можно скачать напрямую;
- интерактивный просмотр реализован лёгким web-компонентом `<model-viewer>` версии 4.2.0;
- модуль просмотра и тяжёлый GLB не загружаются до нажатия кнопки «Загрузить интерактивную 3D-модель».

Обычный каталог и превью автономны. Для вращения 3D-модели страницу следует открыть
через локальный HTTP-сервер; доступ в интернет нужен только для загрузки web-компонента
с Google Hosted Libraries. Сами GLB остаются локальными файлами проекта.

## Как прислать недостающие данные

Для одной позиции достаточно сообщения такого вида:

```text
003
Название на упаковке: ...
Ссылка продавца: ...
Размеры: ...
Фото: приложены
Комментарий: ...
```

ID можно скопировать кнопкой в первой колонке. Для новой детали, которой ещё нет
в таблице, можно написать `новый компонент` — следующий ID будет назначен при добавлении.

## Перегенерация

Из корня проекта:

```powershell
npm.cmd run catalog:generate
npm.cmd run catalog:check
```

Первая команда обновляет HTML, вторая ничего не изменяет и завершается ошибкой,
если опубликованная страница расходится с JSON-источником.

## Открытие без сервера

Можно просто открыть файл:

```powershell
Start-Process .\catalog\catalog.html
```

Так доступны компоненты и двумерные превью. Для интерактивного 3D используйте
локальный mini-server ниже: браузеры часто ограничивают загрузку GLB из `file://`.

## Локальный mini-server

Если удобнее открыть страницу по HTTP:

```powershell
py -m http.server 8080 --bind 127.0.0.1
```

После этого открыть:

```text
http://127.0.0.1:8080/catalog/catalog.html
```

`--bind 127.0.0.1` принципиален: страница должна быть доступна только локально.

Готовая команда для Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\windows\open-component-catalog.ps1
```

Скрипт запускает сервер только на `127.0.0.1` и открывает каталог в браузере.
В исполняемой копии проекта запускайте его из
`%USERPROFILE%\Documents\pesochnica\flagpole\worktree`.
