# Android-приложение Crucian

Это минимальный каркас локального Android-приложения для управления навершием флагштока по BLE.

> Статус v0.6.1: фактический запуск Gradle 8.10.2 блокируется отсутствующим
> Compose Compiler Gradle plugin, обязательным при Kotlin 2.0. Проект также не
> содержит Gradle Wrapper. Подробности и другие риски находятся в
> [`../docs/AUDIT_V061_RU.md`](../docs/AUDIT_V061_RU.md). §android1

Основные принципы:

1. Приложение не использует интернет и не зависит от облака.
2. Приложение подключается только к BLE-устройству с именем **Crucian**.
3. Управление идёт через один пользовательский GATT-сервис и несколько характеристик.
4. Авторизация осуществляется через системный BLE-bonding с PIN-кодом, который задаёт сама ESP32-C3.
5. Смена PIN выполняется отдельной командой уже из защищённой сессии. После смены PIN прошивка удаляет все bond-записи, поэтому старые авторизации перестают действовать.
6. Если BLE не был авторизован в течение первого часа после включения питания, прошивка отключает BLE полностью до следующего сброса питания.
7. Если пользователь успешно подключился и авторизовался, BLE остаётся активным до отключения питания или до явной команды из приложения.

## Почему код Android написан именно так

### 1. Нативный BLE API, без внешних библиотек

Выбран стандартный Android Bluetooth GATT API. Причина простая: проект должен быть переносимым, понятным и без лишней зависимости от чужих библиотек.

### 2. Jetpack Compose вместо XML-экранов

Интерфейс небольшой: текущий статус, режим, яркость, калибровка, смена PIN, выключение BLE. Для такого экрана Compose быстрее поддерживать, а структура кода остаётся компактной.

### 3. Один экран, без сложной навигации

Сейчас приложение решает одну задачу: локально управляет одним устройством. Поэтому сложная навигация, отдельные фрагменты и многоэкранность только усложнят первый прототип.

### 4. Текстовый протокол команд

Команды передаются строками вида `MODE:AUTO`, `BRIGHTNESS:80`, `PIN:123456,654321`.

Такое решение выбрано намеренно:

- легко отлаживать логами;
- легко отправить команду вручную через любой BLE-клиент;
- легко расширять без изменения бинарного формата;
- следующему чату будет проще модифицировать код.

### 5. Парные команды калибровки

Калибровка освещённости реализуется командами `CALIBRATE:DAY` и `CALIBRATE:NIGHT`. Это проще, чем пытаться вычислять универсальные пороги в коде без учёта фактического светового тоннеля и реальных условий установки на крыше или мачте.

## Что обязательно проверить на реальном телефоне

1. Разрешения Android 12+ для `BLUETOOTH_SCAN` и `BLUETOOTH_CONNECT`.
2. Поведение системного pairing-диалога с PIN.
3. Успешность переподключения после выключения и повторного включения питания.
4. Корректность восстановления рекламы BLE после разрыва соединения, пока BLE-сессия разрешена.
5. Поведение после команды выключения BLE.
