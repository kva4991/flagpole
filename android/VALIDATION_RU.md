# Проверка Android-клиента — v0.7.0

## Реализовано в коде

- отдельные состояния сканирования, подключения, MTU, bonding, поиска сервисов, подписки, чтения конфигурации, готовности, отключения и ошибки;
- отдельные тайм-ауты сканирования, подключения, MTU, bonding, поиска сервисов и каждой GATT-операции;
- одна активная GATT-операция и FIFO-очередь остальных операций;
- ожидание callback записи CCCD перед чтением конфигурации;
- современные API записи descriptor/characteristic для Android 13+ и legacy fallback для minSdk 26;
- закрытие `BluetoothGatt`, остановка сканирования, отмена coroutine scope и снятие BroadcastReceiver;
- передача BLE callbacks на main thread;
- отсутствие фиктивного значения батареи;
- generated имя программы и BLE-устройства.

## Проверено локально

- `gradlew.bat :app:assembleDebug --stacktrace` — успешно 2026-08-02;
- Kotlin-компиляция завершена; два предупреждения относятся только к намеренному legacy fallback для API ниже 33.

## Не проверено в текущей среде

- поведение системного PIN-диалога;
- несколько моделей телефонов Android 8–15;
- разрыв связи на каждом этапе;
- отказ операции и восстановление после timeout;
- смена PIN и повторное bonding;
- уничтожение Activity/ViewModel при повороте и уходе приложения в фон.

## Ручные сценарии

1. Первый запуск без разрешений.
2. Bluetooth выключен.
3. Устройство не найдено за 20 секунд.
4. Неверный PIN.
5. Правильный PIN и очередь CCCD → config → STATUS.
6. Десять последовательных команд яркости.
7. Потеря связи во время каждой фазы.
8. Повторное сканирование после ошибки.
9. `BLE:OFF`, затем попытка нового поиска до power cycle.
10. Смена PIN и отказ старого bond.
