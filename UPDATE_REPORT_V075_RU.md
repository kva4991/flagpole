# Подробный отчёт по кумулятивному обновлению v0.7.5

## 1. Основание и границы работы

Проверен актуальный `main` репозитория `kva4991/flagpole`, последний прочитанный коммит: `6bff2d717cb6bb6612e14cd612d2b961627c0617` от 2 августа 2026 года. Текущая исходная версия проекта — v0.7.4.

Изменение не пересматривает размеры корпуса, проводной маршрут, положение лямок, длину светового тоннеля, закладные гайки или печатные STL. Геометрическое изменение только одно: состав презентационной GLB-сцены компоновки электроники исправлен с двух экземпляров крышки на один. Остальные изменения относятся к публикации, идентификации деталей, воспроизводимости и контролю актуальности.

## 2. Что было обнаружено

### 2.1. Исторические модели реально находились в источнике рабочего каталога

В `catalog/drawings.json` были отдельные записи v0.5, среди них:

- общий вид сборки v0.5;
- разнесённый вид v0.5;
- продольный разрез v0.5;
- раскладки PETG/TPU v0.5;
- интерактивная сборка v0.5;
- интерактивные раскладки PETG/TPU v0.5.

`scripts/generateComponentCatalog.mjs` не отбирал `status: current`, а безусловно отображал весь массив. Поэтому надпись «историческая» была лишь предупреждением, а не защитой от открытия неправильного файла.

### 2.2. Идентификаторы деталей были непоследовательны

Реестр из 23 печатных деталей уже существовал, однако:

- часть PNG имела встроенные ID, часть — нет;
- интерактивные GLB не имели ID-hotspots;
- подписи были нанесены в том числе на раскладки печати, где они закрывают контуры и мешают оценке ориентации;
- генератор каталога не проверял, существует ли указанный ID.

### 2.3. В компоновке электроники создавались две крышки

Причина подтверждена в `mechanical/generate_models_v06.py`:

1. `PETG_service_lid` включалась в `electronics_names`, поэтому попадала в сцену в закрытом положении;
2. затем в ту же сцену добавлялась ещё одна копия `PETG_service_lid_raised`, поднятая на 22 мм.

Это был именно сбой презентационной сцены, а не две реальные детали в BOM.

### 2.4. Android-иконка была смешана с техническими чертежами

`docs/android_app_icon_crucian.png` находилась в массиве `drawings`, хотя не является чертежом или 3D-моделью. Она удалена только из технической вкладки; сам файл и Android-ресурс не удаляются.

## 3. Принятые решения и обоснование

### 3.1. Рабочий каталог — только текущая версия

`catalog/drawings.json` переведён на `schemaVersion: 3` и политику:

```json
{
  "visibility": "current-only",
  "currentVersion": "0.7.5"
}
```

Исторические записи удалены из рабочих массивов, но исторические файлы можно сохранять в Git и архивной документации.

**Почему так:** скрытие CSS или подпись «история» не предотвращают случайный выбор. Отсутствующая карточка предотвращает его.

**Дополнительная защита:** генератор HTML теперь завершится ошибкой при любом `status`, отличном от `current`, или версии, отличной от `VERSION.txt`. То есть старую карточку нельзя вернуть одной неосторожной правкой JSON.

### 3.2. Выноски обязательны везде, кроме печатных раскладок

Для 2D принята двухслойная схема:

- исходный SVG/PNG остаётся чистым;
- `mechanical/render_catalog_part_callouts_v075.py` строит подписанную PNG-копию в `catalog/annotated/`;
- координаты цели и подписи хранятся в `catalog/drawings.json` в диапазоне 0…1;
- сами ID рисуются встроенным пиксельным алфавитом, поэтому результат не зависит от системных шрифтов Windows/Linux; проверка сравнивает пиксели, а не байты PNG-сжатия.

Для GLB используются `<model-viewer>` hotspots. Они привязаны к координатам модели в метрах и копируются в полноэкранный viewer.

**Почему не добавлен текст внутрь GLB:** текстовая сетка увеличила бы модель, засорила бы дерево объектов и могла бы быть ошибочно принята за печатную геометрию.

**Почему исходные чертежи чистые:** размерная документация остаётся пригодной для печати, сравнения и последующей генерации. Выноски можно переместить, не меняя инженерный источник.

### 3.3. Печатные раскладки намеренно без ID

У 2D- и 3D-раскладок установлен `kind: "print-layout"` и `calloutMode: "exempt"`. Старые `preview_v06_print_*_ids.png` больше не генерируются и удаляются применителем.

**Почему:** на раскладке важнее видеть плоскую грань, ориентацию, расстояние между объектами и границу стола. Состав очереди однозначно задаётся именами STL и таблицей ID.

### 3.4. Одна поднятая крышка вместо двух

Из `electronics_names` удалён `PETG_service_lid`. Затем в сцену один раз добавляется трансформированный канонический объект:

```python
electronics_scene['PETG_service_lid'] = translate(
    assembly['PETG_service_lid'], [0, 0, 22]
)
```

**Почему сохранено каноническое имя:** ID `#petg-5` относится к одной логической детали независимо от её презентационного положения. Суффикс `_raised` не должен создавать второй тип детали.

### 3.5. Версия повышена до v0.7.5

Хотя STL-геометрия не менялась, изменились публикуемый GLB, все карточки медиа, HTML, правила генерации и интерфейс идентификации. Сохранение номера v0.7.4 сделало бы два различных набора артефактов неразличимыми.

Файлы генераторов `*_v074.py` сохраняются как исторические. Текущая линия копируется в `*_v075.py`; версия и имена выходов обновляются. Стабильные имена `flagpole_finial_v0_6_*.glb` остаются для совместимости и явно рассматриваются как канонические пути, а не номер текущего релиза.

## 4. Изменения по областям

### Каталог

- `catalog/drawings.json` — полный current-only список v0.7.5, метаданные 2D-выносок и 3D-hotspots;
- `scripts/generateComponentCatalog.mjs` — строгая валидация версии/статуса/ID, подписанные превью, hotspots, полноэкранное копирование меток;
- `catalog/README_RU.md` — новое описание политики;
- `catalog/annotated/*.png` — производные подписанные чертежи после запуска генератора.

Текущий состав:

- 19 двухмерных карточек;
- 7 интерактивных моделей, из них 3 печатные раскладки;
- 3 отдельные очереди печати;
- 0 исторических карточек.

### Механика и визуализация

- исправлен блок `electronics_scene` в `mechanical/generate_models_v06.py`;
- добавлен `mechanical/render_catalog_part_callouts_v075.py`;
- добавлен `mechanical/validate_catalog_model_semantics_v075.py`;
- старый `render_part_id_drawings_v06.py` превращается в совместимый вход нового генератора и больше не подписывает print-layout;
- создаются текущие генераторы/выходы с суффиксом `v075` там, где ранее имя содержало `v074`.

### Тесты и CI

- `tests/catalog.test.mjs` проверяет current-only, отсутствие v0.5 в JSON/HTML, все исключения и все ID;
- `tests/mechanicalArtifacts.test.mjs` проверяет v0.7.5, новые генераторы и единственную крышку;
- семантический валидатор открывает GLB и считает узлы крышки;
- `.github/workflows/validate.yml` устанавливает Python-зависимости и запускает новые генераторы/проверки;
- `package.json` получает команды для выносок и проверки семантики моделей;
- `scripts/runPython.mjs` одинаково находит Python 3 через `py -3`, `python3`, `python` или `FLAGPOLE_PYTHON`, поэтому npm-команды не зависят от имени лаунчера в ОС.

### Документация

- ADR-0026 фиксирует долговременное решение;
- `docs/CATALOG_MEDIA_POLICY_RU.md` содержит схему полей и выпускной порядок;
- `AGENTS.md` получает обязательное правило для следующих разработчиков/агентов;
- `CHANGELOG.md`, README, current-status и реестр деталей обновляются до v0.7.5.

## 5. Удалённые из рабочего каталога записи

Из `drawings.json` удаляются исторические ID 103–108 и 201–203. ID не переиспользуются: они остаются исторически занятыми. Карточка 126 (Android-иконка) также исключается из технической вкладки, но файл приложения сохраняется.

Никакие старые GLB/SVG/PNG не требуется удалять из истории Git. Требование относится к их отсутствию в рабочем JSON/HTML.

## 6. Проверки

### 6.1. Проверки самого пакета до упаковки

В изолированном воспроизводимом fixture выполнены:

- синтаксическая проверка всех новых Python/Node-файлов и JSON;
- генерация и повторная проверка 14 подписанных 2D-копий;
- генерация и `--check` HTML-каталога;
- 7 тестов политики каталога — все пройдены; полный синтетический quality gate — 16/16 тестов;
- положительная проверка GLB с одной крышкой;
- отрицательная проверка GLB с искусственно добавленной второй крышкой — валидатор ожидаемо отклонил модель;
- отрицательная проверка исторической карточки v0.5 — генератор ожидаемо завершился ошибкой;
- отрицательная проверка выноски на print-layout — генератор ожидаемо завершился ошибкой;
- двукратное применение обновителя к одному дереву — повторных секций ADR/changelog и второй крышки не появилось;
- полный сценарий применителя на синтетическом checkout прошёл генераторы, semantic check, catalog generate/check, quality gate, checksums и создание полного ZIP с SHA-256.

Полная параметрическая регенерация всех реальных бинарных артефактов, Android и обеих прошивок выполняется уже в целевом checkout штатным quality gate и CI. Этот пакет не содержит второй копии неизменённых бинарников, поэтому до применения к полному checkout такая проверка принципиально недоступна.

После этого вручную открыть `http://127.0.0.1:8080/catalog/catalog.html` и проверить основные ракурсы 204, 205, 209 и 210. Автоматическая проверка подтверждает число и допустимость меток, но эстетическое взаимное перекрытие hotspots зависит от выбранного ракурса браузера.

## 7. Что требует визуального подтверждения после локальной регенерации

- точки 2D-выносок попадают на нужные элементы после фактической отрисовки всех генераторов;
- hotspots удобно читаются на типовых ракурсах и не перекрывают критичные части;
- в модели 210 видна одна поднятая крышка;
- print-layout не содержит ни встроенных, ни viewer-подписей;
- `Ctrl+F5` показывает v0.7.5, а поиск по странице не находит `v0.5` или `история`.

Это не сомнение в структурной правке: причина двойной крышки устранена и проверяется по дереву GLB. Визуальный осмотр нужен для качества расположения подписей.

## 8. Применение и откат

Обычный запуск:

```powershell
powershell -ExecutionPolicy Bypass -File .\APPLY_UPDATE_V075.ps1 "C:\path\to\flagpole"
```

До изменения создаётся ZIP только затрагиваемых файлов. Для полного отката предпочтительно использовать Git; резервный ZIP нужен как дополнительная страховка.

После успешной проверки пользователь может просмотреть diff и самостоятельно выполнить commit/push. Автоматический применитель ничего не публикует в GitHub.

## 9. Замечания интеграции архива

При применении к полному checkout обнаружены и устранены два дефекта самого пакета:

- применитель не передавал выбранный интерпретатор Python во вложенные npm-команды; полный прогон выполнен с `FLAGPOLE_PYTHON`, который штатно понимает `scripts/runPython.mjs`;
- ADR-0026 приведён к обязательному контракту документации проекта: статус `Принято`, разделы рассмотренных вариантов, проверки и условий пересмотра.

Также синхронизированы документы быстрого старта, манифест релиза и версия Android. Эти исправления входят в публикуемое дерево v0.7.5, но отсутствовали в исходном overlay.
