# CAD-процесс build123d для Super_pommels_and_flag

<!-- §cadworkflow -->

## Решение

В проект добавляется только один внешний CAD-инструмент: `pzfreo/build123d-mcp` с тремя его процессными навыками:

- `modeling` — пошаговое построение и измерение B-Rep-геометрии;
- `drawing` — получение основных видов, сечений и размеров;
- `repair` — локализация и исправление невалидных операций/тел.

`text-to-cad`, `draftwright` и `blender-industrial-kit` не становятся обязательными зависимостями. Первый дублирует уже существующие правила репозитория, второй имеет смысл только после появления устойчивых STEP, третий относится к Blender-визуализации, а не к производственному источнику геометрии.

## Подключение MCP

Локальный сервер запускается агентом как подпроцесс:

```text
command: uv
args: ["tool", "run", "--python", "3.12", "build123d-mcp@latest"]
```

После подключения доступны процессные инструкции:

```text
install_skill(target="agents-md", skill="modeling")
install_skill(target="agents-md", skill="drawing")
install_skill(target="agents-md", skill="repair")
```

Их полный автоматически сгенерированный текст не копируется в корневой `AGENTS.md`: проектные правила ID, каталога, версий и публикации уже закреплены там и остаются единственным источником истины.

## Иерархия источников

Для новой CAD-детали действует цепочка:

```text
build123d Python source → STEP → STL/GLB → чертежи/превью → каталог
```

Редактируется Python-источник. STEP — основной обменный B-Rep-артефакт, но не самостоятельный ручной источник. STL, GLB, PDF, SVG и DXF являются производными файлами.

Текущий `mechanical/generate_models_v06.py` остаётся рабочим источником SDF/trimesh-геометрии до завершения поэтапной миграции. Подключение MCP само по себе не объявляет существующие посадки физически подтверждёнными.

## Пилот миграции

Перенос начинается только с трёх ограниченных деталей:

1. `#petg-6` — световой тоннель: цилиндры, клеевая полка, окно и сечение;
2. `#petg-10` — опора VEML7700: отверстия, межосевые размеры и M3;
3. `#petg-5` — сервисная крышка: сопряжение, паз TPU и сборочное сечение.

Половины ротора переносятся только после того, как эти три пилота проходят проверки и не требуют ручной правки производных файлов.

## Обязательный цикл

1. Построить одну операцию.
2. Отрендерить или измерить результат.
3. Проверить критические размеры и именованные зазоры.
4. Выполнить `validate()`.
5. Экспортировать STEP.
6. Получить STL из того же тела.
7. Сравнить габариты и объём с текущим артефактом.
8. Сформировать основные виды и обязательные сечения.
9. Выполнить проектный quality gate.

## Критерии принятия пилотной детали

- тело валидно и замкнуто;
- STEP воспроизводимо строится из Python;
- один стабильный ID используется в исходнике, имени STEP-тела, STL, чертеже и каталоге;
- измерены габариты, отверстия, глубины пазов, стенки и посадочные зазоры;
- чертёж содержит изометрию, спереди, сверху, сбоку и требуемое сечение;
- STEP/STL/PDF/SVG/DXF не исправлялись вручную после генерации;
- физически непроверенные размеры по-прежнему помечены как предварительные.
