# Вращающееся навершие флагштока Super_pommels_and_flag v0.7.6

Super_pommels_and_flag — экспериментальный проект вращающегося навершия для небольшого флага с подсвеченным контуром рыбы. Репозиторий объединяет печатную механику PETG/TPU, подсветку 12 В, прошивку ESP32-C3, BLE-управление, Android-приложение и автономный каталог компонентов, чертежей и 3D-моделей.

Актуальная кумулятивная версия — **v0.7.6**. Все 23 канонические печатные детали теперь строятся как native build123d/OCP B-Rep; переходные и legacy-сетки не используются как источник производственной геометрии.

Основные изменения:

- на всех текущих винтовых соединениях предусмотрены обслуживаемые закладные M4/M3 и отдельные купоны для обеих гаек;
- два провода Ø2 мм проходят по открытой приподнятой дорожке с просветом 4,2 мм и бортами 2,5 мм ниже крепежа;
- на нижнем скруглении `#petg-2` установлен цельный TPU95-держатель `#tpu95-10` с двумя закрытыми каналами, направленный примерно на 35° вниз к флагу;
- верхняя лямка привязана к нижней кромке навершия: верхняя линия пришивания находится на 10 мм ниже неё;
- световой тоннель VEML7700 укорочен до 15 мм и получил отдельную клеевую полку с кольцевым резервуаром;
- карман AHT20+BMP280 рассчитан на мембрану [#019](catalog/catalog.html#component-019); её физические размеры берутся из единого реестра, рисунок отверстий — из CAD;
- в боксе добавлен съёмный двухуровневый каркас: DC-DC снизу, ESP32-C3 и MOSFET вертикально на противоположных стенках, VEML7700 на отдельной опоре;
- ненужные карточки контактного листа и растрового образца рыбы заменены рабочими картами крепежа и компоновки электроники.

Жёсткие детали рассчитаны на уже купленный оранжевый PETG. TPU 95A используется для функциональных мягких элементов, TPU 85A — для статических прокладок. ASA остаётся возможной будущей заменой после повторной печати купонов.

## С чего начать

1. Прочитать [быстрый вход для нового чата](docs/agent-fast-start.ru.md).
2. Проверить [текущий статус реализации](docs/current-implementation-status.ru.md).
3. Открыть [отчёт v0.7.6](UPDATE_REPORT_V076_RU.md) и [аудит чертежей](docs/DRAWING_AUDIT_V074_RU.md).
4. Перед изменением архитектуры открыть [индекс ADR](docs/architecture/decisions/README.ru.md).
5. Перед печатью заполнить [таблицу обязательных измерений](MEASUREMENTS_REQUIRED_RU.md).
6. Компоненты, изображения и вращаемые 3D-модели смотреть в [локальном каталоге](catalog/catalog.html). Перед изменением конкретного рисунка/3D открыть его отдельное подробное описание по тому же ID в [`catalog/media-descriptions/`](catalog/media-descriptions/README_RU.md).
7. Условия использования аппаратной и программной частей смотреть в [карте лицензирования](LICENSE.md).

## Локальный каталог компонентов, чертежей и 3D

Физические размеры покупных деталей редактируются только в [`catalog/physical-components.json`](catalog/physical-components.json). На локальном сайте каждая позиция имеет постоянную ссылку вида `catalog/catalog.html#component-015`; описания моделей ведут туда и не копируют размеры. §physicalcomponents1

Основная карточка #204 показывает каноническую build123d-сборку всех 23
печатных деталей. Отдельной экспериментальной вкладки больше нет. В
полноэкранном режиме независимо переключаются ID и упрощённый крепёж.

Из корня проекта выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\windows\open-component-catalog.ps1
```

Скрипт запускает сервер только на `127.0.0.1`, открывает `catalog/catalog.html` и оставляет интерактивные GLB доступными для вращения. Остановить сервер можно сочетанием `Ctrl+C`.

Чтобы открыть каталог именно в Firefox:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\windows\open-component-catalog.ps1 -Browser Firefox
```

## Проверки

Полная регенерация моделей, схем и каталога с последующей валидацией запускается из синхронизированной защищённой копии:

```powershell
.\build.cmd all
```

Доступны также режимы `generate`, `validate` и `catalog`. Большие `*.stl` и `*.glb` хранятся через Git LFS; PNG остаются обычными файлами Git. GitHub Actions скачивает LFS только для условной механической задачи.

Программные проверки подтверждают воспроизводимость файлов и топологию STL. Они не подтверждают посадки реальных деталей, герметичность, прочность, нагрев, срок службы на солнце или работу электроники.
