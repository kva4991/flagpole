## Что считается рабочим каталогом

`catalog/catalog.html` — оперативная страница для сборки и проверки текущей версии. Она не является музеем всех выпущенных вариантов. В ней публикуются только записи `status: "current"`, версия каждой записи обязана совпадать с `VERSION.txt`.

Исторические файлы допустимо сохранять в Git, `archive/`, отчётах прошлых выпусков и ссылках changelog. Добавлять их в массивы `drawings`, `models` или `printSessions` нельзя.

## Единственное подробное описание каждого медиа-ID

Для каждой записи `drawings`, `models` и `printSessions` обязателен `descriptionFile` вида `catalog/media-descriptions/<ID>.md`. Один ID имеет ровно один файл, один файл относится ровно к одной карточке. Имя файла, `id` во front matter, ID карточки, тип медиа, статус, версия, основной `mediaFile` и существующий `sourceOfTruth` проверяются автоматически. §mediarationale1

`catalog/drawings.json` хранит структуру и технические метаданные. Поле `description` в нём запрещено, чтобы инженерное обоснование не расходилось между JSON, HTML и документацией. Краткая карточка получает `summary` из ID-файла, полный текст остаётся читаемым Markdown и открывается из каталога. Сгенерированный HTML является производным отображением и не считается вторым редактируемым источником.

В ID-файле обязательно фиксируются:

- короткий критический контракт в начале: элементы, которые нельзя потерять, прямые запреты и проверки после генерации;
- назначение вида и его границы: что он подтверждает и чего не подтверждает;
- исходный CAD/SVG-генератор, производные PNG/GLB/STL и связанные тематические документы;
- полный состав показанных печатных и непечатных тел, крепежа, проводов, мембран, окон, материалов и служебных зон;
- причины выбранной геометрии, ориентации, ракурса, разреза, разнесения, цвета, прозрачности и упрощения;
- значение всех component-ID, part-ID и feature-ID, важных для чтения вида;
- сборочная, эксплуатационная и сервисная последовательность;
- все предварительные размеры, непроверенные допущения и обязательные физические испытания;
- точный перечень файлов, которые нужно обновлять одновременно, и проверок после изменения.

Перед моделированием агент обязан сначала прочитать компактный критический контракт, затем весь ID-файл. Любая правка геометрии, компоновки, выносок, путей файлов, визуальной семантики или инженерного объяснения обновляет оба слоя в той же правке. Тематические документы не удаляются, если описывают подсистему шире одной карточки; удаляется только повторяющееся медиа-специфичное объяснение. Связь ID и rationale закреплена ADR-0032, краткий обязательный контракт — ADR-0033. §mediacontract1

Проверка также ищет дословные summary и существенные rationale-фрагменты вне ID-папки, чтобы старый параллельный текст не вернулся:

```powershell
npm.cmd run media:descriptions:check
```

## Правило миниатюр и управления метками

- `thumbnail` обязателен для каждой 2D-карточки и не может ссылаться на `catalog/annotated/` либо файл `_ids.png`;
- `annotatedPreview` используется только при открытии полного overlay-чертежа;
- embedded-документы получают отдельную чистую миниатюру;
- hotspots непечатных GLB скрыты в карточке и видны в полноэкранном viewer;
- рядом с крестиком полноэкранного viewer обязательна доступная кнопка `ID` с `aria-pressed`;
- `labelPosition` — только предпочтительное направление, фактическая рамка размещается автоматическим resolver рядом с `target`;
- отчёт `mechanical/CALLOUT_LAYOUT_REPORT_V076.json` является производным проверяемым артефактом.
<!-- v076-thumbnail-policy:end -->

Все текущие чертежи и 3D-модели должны показывать ID изображённых деталей. Единственное исключение — раскладки для печати.

### Двухмерные чертежи

Для обычного чертежа используется:

```json
{
  "kind": "drawing",
  "calloutMode": "overlay",
  "preview": "mechanical/example.png",
  "annotatedPreview": "catalog/annotated/123_example_ids.png",
  "callouts": [
    {
      "id": "#petg-5",
      "label": "Сервисная крышка",
      "target": [0.52, 0.31],
      "labelPosition": [0.78, 0.12]
    }
  ]
}
```

Координаты нормированы от `0` до `1`: `[0, 0]` — левый верхний угол, `[1, 1]` — правый нижний. Исходный SVG/PNG не редактируется ради подписей. Подписанная копия строится командой:

```powershell
python mechanical/render_catalog_part_callouts_v075.py
```

Если документ сам является таблицей ID или уже имеет встроенные корректные выноски, используется `calloutMode: "embedded"` и непустой массив `partIds`.

### Интерактивные 3D-модели

Для обычной модели используется `calloutMode: "hotspots"`. `position` задаётся в метрах в системе координат GLB, `normal` определяет сторону метки:

```json
{
  "id": "#petg-9",
  "label": "Каркас электроники",
  "position": [-0.047, 0.0, 0.030],
  "normal": [0, 1, 0]
}
```

Нельзя добавлять текстовые сетки в GLB ради подписей: они увеличивают файл, засоряют сцену и могут быть приняты за печатную геометрию. Подписи принадлежат каталогу и автоматически копируются в полноэкранный viewer.

### Раскладки для печати

Для 2D- и 3D-раскладок:

```json
{
  "kind": "print-layout",
  "calloutMode": "exempt",
  "calloutExemptReason": "Раскладка печати должна оставаться без перекрывающих подписей."
}
```

`callouts`, `partIds` и `annotatedPreview` у такой записи не задаются. Состав очереди сверяется по таблице ID и именам STL, а не по подписям поверх стола.

## Допустимые ID

- Компоненты и покупные детали: строки `001`…`099` из `catalog/components.json`.
- Печатные детали: ID из `mechanical/part_id_registry_v06.json`.
- Свободные подписи без ID запрещены: сначала нужно создать или выбрать канонический ID.

## Физические размеры покупных компонентов

`catalog/physical-components.json` — единственный редактируемый источник физических размеров и массы компонентов `001`…`099`. Каждое значение содержит статус и источник. Каталог объединяет его с `components.json` по цифровому ID и публикует постоянную ссылку `catalog/catalog.html#component-<ID>`. §physicalcomponents1

Актуальные документы и ID-описания должны ссылаться на соответствующую карточку, а не повторять значение. Размеры печатной геометрии остаются в параметрическом CAD и его диагностике. Исторические ADR и отчёты могут сохранять старое число как зафиксированный контекст решения.

## Добавление нового вида

1. Создать или обновить первичный генератор/SVG/GLB.
2. Добавить только текущую карточку в `catalog/drawings.json`, назначить `descriptionFile` и не добавлять поле `description`.
3. Создать или полностью обновить `catalog/media-descriptions/<ID>.md`, сверив его с первичным источником и фактическим составом медиа.
4. Нанести метаданные выносок либо оформить исключение `print-layout`.
5. Для 2D выполнить `python mechanical/render_catalog_part_callouts_v075.py`.
6. Выполнить `npm.cmd run media:descriptions:check` и `npm.cmd run catalog:generate`.
7. Открыть локальную страницу и проверить, что линии указывают на нужные детали, hotspots не перекрывают друг друга при основных ракурсах, а полноэкранный режим сохраняет ID и ссылку на полный ID-файл.
8. Выполнить проверки и обновить контрольные суммы.

## CAD-заготовка без производных файлов

Если владелец прямо запрещает генерацию, нельзя создавать пустой STL/STEP/GLB/PNG или добавлять обычную медиа-карточку с несуществующим файлом. Размерный JSON заготовки перечисляется в `catalogPolicy.cadDraftSources`, имеет статус `source-only-not-generated`, ссылается на воспроизводимый opt-in исходник и технический документ. Сайт показывает параметры и простую HTML-схему в существующей вкладке «Чертежи и 3D». Правило применяется и к жёсткой #401, и к гибкой #402. §bearingadapter1 §lowercablestrain1

После разрешённой генерации заготовка проходит обычный CAD-аудит, получает канонический part-ID/медиа-ID и производные файлы; статус source-only удаляется. До этого она не входит в количество сгенерированных печатных деталей и не может называться готовой к печати.

## Запрет дублирования презентационных деталей

Разнесение или поднятие детали выполняется трансформацией единственного канонического объекта. Нельзя сначала включить объект в базовый набор сцены, а затем добавить его копию под другим presentation-именем. Для модели 210 это проверяет `mechanical/validate_catalog_model_semantics_v075.py`.
