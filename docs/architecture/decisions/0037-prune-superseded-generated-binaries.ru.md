# ADR-0037: не хранить устаревшие бинарные генерации в текущем дереве

- Статус: Принято
- Дата: 2026-08-04

## Контекст

В рабочем дереве одновременно находились актуальные build123d-файлы, бинарные
генерации v0.5, переходные сетки v0.7.3, дубли старых STL/купонов и завершённый
трёхдетальный build123d-пилот. Эти файлы не показывались текущим каталогом и
увеличивали размер checkout примерно на 272 МиБ без пользы для сборки.

## Рассмотренные варианты

- оставить все исторические бинарные файлы рядом с актуальными;
- перенести их в ещё один каталог `archive/` внутри репозитория;
- удалить производные исторические файлы из текущего дерева и использовать Git как архив;
- удалить также `generate_models_v06.py` немедленно.

## Решение

Удалить из текущего дерева:

- v0.5 GLB, STL, купоны, превью, генератор и его манифесты;
- переходные бинарные материалы v0.2/v0.7.3 из `archive/`;
- завершённый build123d-пилот и его отдельный генератор;
- генераторы и изображения v0.7.4, заменённые текущими v0.7.5/v0.7.6.

Историю получать из Git. Лёгкие текстовые отчёты прошлых выпусков сохранять,
если они объясняют происхождение решений. `generate_models_v06.py` временно
оставить: он нужен трём актуальным непечатным сценам `#205`, `#209`, `#210` и
нескольким 2D-генераторам, импортирующим его параметры. §prunegen1

## Последствия

- новый checkout и LFS-загрузка становятся заметно меньше;
- в текущем дереве остаётся только одна печатная линия build123d;
- старый релиз при необходимости извлекается по тегу или коммиту Git;
- `generate_models_v06.py` нельзя считать источником актуальных печатных STL;
- удаление оставшегося справочного генератора требует предварительного переноса его параметров и трёх сцен.

## Проверка

После удаления выполнить поиск всех удалённых путей, проверку ссылок,
`npm.cmd test`, генерацию каталога и проверку контрольных сумм. Убедиться, что
все файлы из `catalog/drawings.json` и текущих манифестов существуют.

## Когда пересматривать

Решение пересматривается, если проекту потребуется автономная поставка старого
релиза без доступа к Git либо если появится отдельный внешний архив релизных
артефактов с формально закреплённой политикой хранения.
