# ADR-0004: README, focused docs, ADR и локальный quality gate

- Статус: Принято
- Дата: 2026-08-01
- Теги: §docqa01 §adrproc §impact §checksum

## Контекст

Проект проходит через несколько чатов и сочетает механику, питание, прошивку и Android. Один растущий handoff смешивает текущую реализацию, планы и историю, а ручные ссылки легко ломаются.

## Рассмотренные варианты

1. Продолжать вести один большой файл передачи.
2. Копировать весь процесс крупного программного проекта без адаптации.
3. Использовать компактный многоуровневый процесс с автоматической проверкой.

## Решение

Принят третий вариант: публичные README, быстрый вход, изменяемый current status, тематические документы, последовательные ADR, карта §-тегов, аудит ссылок, карта влияния, тесты и SHA-256 manifest.

## Последствия

Каждое изменение должно обновлять правильный уровень документации. Локальные Node-инструменты остаются без внешних runtime-зависимостей и не подменяют аппаратный стенд.

## Проверка

Запустить `npm.cmd run quality:docs:all`, `npm.cmd run catalog:check`, `npm.cmd test`, `npm.cmd run review:impact` и `npm.cmd run checksums:check`.

## Когда пересматривать

Если репозиторий вырастет настолько, что полный аудит станет медленным, либо появится CI, требующий раздельных быстрых и полных профилей.
