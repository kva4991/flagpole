# ADR-0034: единый реестр физических размеров компонентов

- Статус: Принято
- Дата: 2026-08-04

## Контекст

Размеры покупных плат, древка, подшипников, мембраны, проводов и других физических компонентов повторялись в карточках, текущей документации и пояснениях 3D-моделей. После измерения реального древка старые значения остались в нескольких местах и могли привести к печати несовместимой геометрии.

Размеры печатных деталей имеют другую природу: они выводятся параметрическим CAD и не должны смешиваться с измерениями покупных объектов.

## Рассмотренные варианты

- оставить размеры в `components.json` и вручную повторять в документах — отклонено из-за расхождений;
- создать отдельный вручную заполняемый Markdown-каталог — отклонено как второй производный источник рядом с веб-страницей;
- хранить физические значения в одном структурированном JSON, объединять его с карточками при генерации сайта и ссылаться на стабильные якоря — принято.

## Решение

`catalog/physical-components.json` содержит ровно одну запись для каждого ID из `catalog/components.json`. Каждое значение имеет стабильный ключ, отображаемое значение, единицу, статус и источник. Допустимые статусы различают измерение, расчёт, стандарт, данные продавца, данные размерной фотографии и предварительное допущение.

`catalog/components.json` сохраняет назначение, варианты названия, электрические характеристики, ссылки и неразмерные пояснения. Физические размеры и масса там не дублируются.

Генератор объединяет два JSON по ID и создаёт стабильные адреса `catalog/catalog.html#component-<ID>`. Актуальные README, тематические документы и `catalog/media-descriptions/<ID>.md` ссылаются на конкретную карточку вместо копирования физического числа. §physicalcomponents1

Численные размеры печатных тел, отверстий, пазов и посадок остаются в параметрическом CAD и его машинном отчёте. Исторические ADR и отчёты могут сохранять значения времени принятия решения, если их исторический статус очевиден.

## Последствия

- новый замер редактируется один раз и автоматически появляется на сайте;
- модельные описания имеют точные ссылки на исходные физические данные;
- вычисленные значения, например овальность, явно отделены от прямых измерений;
- изменение размера компонента не означает автоматическую регенерацию CAD: сначала оценивается влияние, затем по отдельному решению обновляются модели;
- пустая запись допустима и показывает, какие размеры ещё нужны.

## Проверка

- генератор требует полного совпадения ID двух JSON;
- якорь обязан иметь формат `component-<ID>`;
- ключи измерений внутри карточки уникальны;
- статус и источник каждого значения обязательны;
- `npm.cmd run catalog:check` проверяет JSON и синхронизацию HTML;
- тесты проверяют наличие постоянной ссылки и вывод размеров для каждой карточки.

## Когда пересматривать

- если физические измерения станут напрямую импортироваться из системы метрологии;
- если CAD начнёт читать численные интерфейсные параметры из отдельной строго типизированной схемы;
- если один component-ID начнёт описывать несколько фактически разных экземпляров с независимыми картами измерений.
