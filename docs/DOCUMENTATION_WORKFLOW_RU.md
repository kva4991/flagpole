# Процесс ведения документации

<!-- §docqa01 -->

Метод адаптирован к Crucian из практики проекта Sheepfold: пользовательский README отделён от технических контрактов, текущее состояние — от истории решений, а навигация и внутренние ссылки проверяются локально.

## Уровни документации

1. `AGENTS.md` — полный операционный контракт для следующих агентов: порядок работы, источники истины, обязательная синхронизация каталога и чертежей, проверки и Git-гигиена.
2. `README.md` и `README.ru.md` — краткое публичное описание и безопасная точка входа.
3. `docs/current-implementation-status.ru.md` — изменяемая фотография текущего состояния.
4. Тематические документы — подробное актуальное поведение конкретной подсистемы.
5. `catalog/physical-components.json` — единственный источник физических размеров и массы покупных деталей; сайт предоставляет стабильные ссылки на каждую запись. §physicalcomponents1
6. `catalog/media-descriptions/<ID>.md` — единственное медиа-специфичное объяснение каждого чертежа, 3D-вида или очереди печати; его читают до моделирования и обновляют вместе с источником и производными файлами. §mediarationale1
7. `mechanical/cad_drafts/*.json` — единые размеры исходных CAD-заготовок без производных файлов; каталог показывает их с явным статусом, будущий генератор читает тот же JSON. §bearingadapter1
8. `docs/architecture/decisions/` — неизменяемая история устойчивых архитектурных решений.
9. `docs/dev/tag-map.md` — стабильные §-теги, связывающие правила, rationale и проверки.
10. `docs/AUDIT_*.md` — датированный анализ с явной границей доказательств.

## Правило изменения

- Исправление текста текущего состояния обновляет статус или тематический документ.
- Новое устойчивое архитектурное решение получает следующий последовательный ADR.
- Принятый ADR не переписывается для нового вывода; новый ADR помечает предыдущий заменённым.
- Изменение кода или схемы в той же сессии обновляет связанный документ и при необходимости карту тегов.
- Любая принятая в разговоре мелочь, влияющая на размер, форму, материал, монтаж, запрет или критерий проверки, в той же сессии переносится в соответствующий источник истины и ближайший тематический документ. Переписка не считается хранилищем требований; при устойчивом выборе дополнительно обновляется ADR или сводка решений.
- Предположение всегда помечается как предположение; физическое измерение содержит способ, дату и единицы.
- Аппаратное подтверждение нельзя выводить из успешного линтера, синтаксической компиляции или изображения схемы. §status1
- Изменение BOM, материала, покупной позиции или изображения обновляет `catalog/components.json`; физический размер, масса, статус и источник значения обновляются только в `catalog/physical-components.json`. Актуальный документ ссылается на `catalog/catalog.html#component-<ID>` вместо копирования числа. Изменение геометрии, схемы, превью, пути, ракурса, выносок или состава моделей обновляет связанный `catalog/media-descriptions/<ID>.md` и при необходимости структуру `catalog/drawings.json`.
- Подробное объяснение конкретного медиа хранится только в ID-файле. Повторяющее поле `description` в `drawings.json` и параллельный редактируемый текст в другом документе запрещены; тематическая документация сохраняется, если её область шире одной карточки.
- После изменения JSON-источников или ID-файлов каталог перегенерируется; `catalog/catalog.html` нельзя править вручную.
- Заготовка без генерации не получает фиктивные медиафайлы: размерный JSON, opt-in исходник и технический документ добавляются вместе, а на сайте выводится статус `source-only-not-generated`.

## Автоматические проверки

```powershell
npm.cmd run media:descriptions:check
npm.cmd run quality:docs:all
npm.cmd run catalog:check
npm.cmd test
npm.cmd run review:impact
```

`media:descriptions:check` проверяет связь 1:1 между карточками и ID-файлами, обязательные разделы, метаданные, существование `mediaFile`/`sourceOfTruth`, отсутствие дублирующего `description` в JSON и отсутствие повторов summary/существенных rationale-фрагментов в других редактируемых файлах. `quality:docs:all` проверяет относительные Markdown-ссылки, зарегистрированные §-теги и упомянутые npm-команды без обращения в интернет. `catalog:check` подтверждает, что HTML воспроизводится из JSON и Markdown-описаний. Тесты защищают формат ADR и карту влияния.

## Контрольные суммы

`CHECKSUMS_SHA256.txt` охватывает публикуемое дерево, кроме самого manifest и локальных build/cache-каталогов.

```powershell
npm.cmd run checksums:update
npm.cmd run checksums:check
```

Обновление manifest выполняется после завершения осмысленных правок, а проверка — перед публикацией. §checksum

## Граница метода

Документальный quality gate ловит потерянные ссылки, незарегистрированные теги, рассинхронизацию каталога и нарушение формата ADR. Он не проверяет истинность инженерных утверждений, электрическую безопасность, прочность, герметичность, BLE-совместимость или поведение на конкретной плате.
